# `fh3.0/v5/reth-bsc-dev` goldens

Snapshots for the `bnb-dev` network when the Firehose blocks are produced by the
StreamingFast **reth-bsc** fork (running as a follower of the dockerized geth-BSC
miner, see `scripts/run_firehose_reth_bsc.sh`). Run with:

```bash
pnpm test:fh3.0:reth-bsc-dev
```

The suite must run against a **fresh chain** (`scripts/bnb/up.sh -c` + a fresh
follower). On a reused chain the fresh-chain-only tests fail (skippable with
`SKIP_FRESH_CHAIN_ONLY_TESTS=1`) and `prague/setcode_set_delegations` shifts by
one ordinal because its fixed authority EOA already exists.

## Why a separate tag from `fh3.0/bnb-dev`

The `fh3.0/bnb-dev` goldens are generated by the geth-BSC Firehose tracer. The
reth Firehose tracer (protocol version 5) intentionally does **not** emit gas
change events, so ordinals can never line up with the geth goldens. Like the
other reth flavors (`fh3.0/v5/reth-dev`, …), reth-bsc gets its own tag, seeded
from its own output with `SNAPSHOTS_UPDATE=true`.

## Divergence from the geth-BSC goldens (audited 2026-08-05)

Of the 65 snapshots that have a `fh3.0/bnb-dev` counterpart, **57 are
byte-identical** once `gasChanges` and all `ordinal`/`beginOrdinal`/`endOrdinal`
fields are stripped. The remaining 8 fall into three classes, each of which also
exists between `fh3.0/v5/reth-dev` and `fh3.0/geth-dev` — i.e. they are generic
reth-vs-geth Firehose tracer differences, not BSC-specific ones:

1. **`failureReason` strings** (revm wording vs geth wording):
   - `precompile error` vs `point is not on curve`
     (`calls/complete_call_tree`)
   - `contract creation code storage out of gas` vs `out of gas`
     (`deploys/contract_fail_intrinsic_gas`)
2. **Self-destruct where beneficiary == killed contract**: geth emits a net-zero
   `SUICIDE_WITHDRAW` + `SUICIDE_REFUND` balance-change pair; reth omits it
   (`suicide/contract_and_suicide_beneficiary_are_the_same*`).
3. **Destroyed-account state clearing**: reth records the cleanup events — a
   `codeChange` (old code → empty) and a `nonceChange` (n → 0) — while geth
   suppresses them (`suicide/create_contract_*kill*`,
   `suicide/create_contract_suicide_in_constructor`).

Six snapshots have no `fh3.0/bnb-dev` counterpart at all (SetCode,
self-transfers, storage-OOG, …): those tests were added after the last geth-BSC
golden run, so there is nothing to compare against.

In short, consumer-visible divergence from geth-BSC Firehose blocks is: no gas
changes, shifted ordinals, plus the three classes above — the same contract as
the Ethereum reth Firehose tracer.
